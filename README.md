# bid-evidence-index

为技术标或商务标 Word 增补素材小标题、章节论证说明和可点击的三列证据索引，也支持按新版材料微调已有索引。

索引按“招标诉求 → 已有材料事实 → 可核验结论”组织，让阅读者知道本章响应什么、材料能证明什么、在哪里核查。只使用已提供或获授权访问的资料，不编造证据、评分条件或得分承诺。

## 准备两类文件

1. **招标要求**：招标文件及适用的澄清补遗。
2. **待改标书**：技术标或商务标，优先提供原始 `.docx`。

如有多个版本，请说明以哪一版为准。无需预先制作素材清单。

## 使用方式

### 在 Codex 中安装

1. 在本仓库点击 **Code → Download ZIP**，下载并解压。
2. 将解压后的文件夹重命名为 `bid-evidence-index`，确认文件夹内直接包含 `SKILL.md`。
3. 将整个文件夹放入本机的 `~/.codex/skills/` 目录。若设置了自定义 `CODEX_HOME`，则放入其 `skills` 子目录。
4. 在新的 Codex 对话中附上招标要求和待改标书，调用下面的技能指令。

其他支持 `SKILL.md` 的客户端，按其技能安装方式放置整个目录；不能只复制入口文件，需保留 `references` 和 `scripts` 等子目录。

### 开始整理

安装后，附上文件并调用：

```text
请使用 $bid-evidence-index，依据附件中的招标要求和商务标书，
保留原目录及全部材料，补充必要的小标题、章节论证说明和三列跳转索引，
交付修改后的 Word 及改动明细。
```

只需微调指定列时，可以这样说：

```text
请使用 $bid-evidence-index，按最新版材料修正现有索引的中间列和右列。
只改必要文字和跳转；左列、表头、正文、图片及材料顺序均不动。
```

全新索引默认采用：

| 招标诉求与评审关注 | 响应说明与证据链 | 证明材料及跳转 |
| --- | --- | --- |
| 要求及条款来源 | 已有事实、证据对应关系和结论范围 | 素材名称及真实文内链接 |

## 默认保护原件

- 原件只读，另存整改稿；保留原目录、标题、正文、表格、图片、材料顺序和图片尺寸。
- 已有准确标题优先沿用，仅对缺少标题的材料增补中性小标题。
- 指定列微调只修改获准单元格，不扩大到其他章节或原材料。
- 只有明确要求精简或重组时，才调整材料；完整原版仍保留，并记录取舍。
- 目录页码因增补而变化时，保留目录条目与层级，单独记录页码刷新。

## 交付内容

- **整改后的 Word**：例如 `原名_索引优化版.docx`。
- **改动明细**：列明位置、修改前后、原因及跳转目标，通常为简明 Markdown 文件。

编辑和渲染依赖运行环境提供的文档工具。交付前应核对内容保留、链接实际落点和页面显示；无法完成的验证需如实说明。工作底稿、审计报告和页面预览默认不作为交付附件。

## 附带的只读审计脚本

脚本需要 Python 3.9 或以上，仅使用标准库。在技能目录中运行：

```bash
# 盘点原文档
python scripts/audit_docx.py source.docx --out before.json

# 比较原文档与整改稿
python scripts/audit_docx.py source.docx result.docx --out comparison.json
```

脚本只读取输入文档，另写 JSON 报告；不编辑 Word、不更新目录、不渲染页面，也不访问文档中的外部链接。报告包含 ZIP 部件、图片引用及部分显示属性、书签、域、链接和目录等检查线索。

**退出码 0 只表示报告成功写入，不表示文档验收通过。** 脚本不能认证证据真实性、论证准确性、全部原文保留或视觉效果，仍需结合改动清单进行内容核对和页面检查。报告可能含文档路径、文字摘要及链接，应按原文档的保密要求处理。

技能中的示例均为虚构写法，不含真实投标材料，也不能直接当作投标事实使用。
